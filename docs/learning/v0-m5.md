# V0-M5 — CMake, testing và debugging workflow

## Mục tiêu

Biến V0 thành một project có build lặp lại, test tự động và quy trình debug
cho memory, thread và system call.

## Core cần học

### CMake

CMake mô tả target, source, include directory, compiler option và dependency.
Nó không trực tiếp compile code; generator tạo build files để compiler và
linker thực hiện công việc.

### Debug build

Debug build có symbol và thường không tối ưu mạnh, giúp GDB liên kết instruction
với source line và variable.

### Công cụ debug

- GDB: breakpoint, stack, thread, variable và control flow.
- Valgrind Memcheck: invalid read/write, use-after-free và memory leak.
- AddressSanitizer: memory bug nhanh hơn trong lúc chạy.
- UndefinedBehaviorSanitizer: undefined behavior.
- ThreadSanitizer: data race giữa các thread.
- `strace`: system calls và tương tác với kernel.

Không công cụ nào thay thế hoàn toàn công cụ khác.

## Thread/multithread trong V0

Khi debug code đa thread, cần phân biệt:

```text
GDB             → thread nào đang chạy, đang ở dòng nào
ThreadSanitizer → thread nào cùng truy cập memory không hợp lệ
Valgrind        → memory access/leak
strace          → process/thread gọi kernel như thế nào
```

Test queue tạo 300 event, lớn hơn capacity 4, để exercise cả producer blocking
và consumer draining. Test zero-sample kiểm tra shutdown không có event.

## Sanitizer build

AddressSanitizer:

```sh
cmake -S . -B build-asan -DCMAKE_BUILD_TYPE=Debug -DSANITIZER=address
cmake --build build-asan
ctest --test-dir build-asan --output-on-failure
```

ThreadSanitizer:

```sh
cmake -S . -B build-tsan -DCMAKE_BUILD_TYPE=Debug -DSANITIZER=thread
cmake --build build-tsan
ctest --test-dir build-tsan --output-on-failure
```

ThreadSanitizer chỉ báo race trong code thực sự được gọi. Hàm
`run_sensor_threads_unsafe()` được giữ làm learning experiment, nhưng không
được gọi bởi normal executable/test vì nó cố ý chứa data race.

## Interview checkpoint

Trước V1, cần giải thích được:

- CMake target và dependency hoạt động thế nào;
- khác nhau giữa GDB, Valgrind, sanitizer và `strace`;
- vì sao test queue phải kiểm tra shutdown và queue-full;
- vì sao data race cần ThreadSanitizer thay vì chỉ Valgrind;
- cách debug một chương trình có nhiều thread.
