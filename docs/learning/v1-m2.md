# V1-M2 — Unix Domain Socket IPC

## Mục tiêu

Truyền telemetry từ `sensor_service` process sang `vehicle_middleware`
process bằng Unix Domain Socket.

Milestone này dùng Linux abstract Unix socket namespace (`@...`) để chạy được
trong sandbox mà không cần tạo file. Trong deployment thực tế, có thể đổi sang
filesystem socket path trong một runtime directory được cấu hình.

## Core cần học

Process không tự chia sẻ heap. IPC tạo một communication boundary do kernel
quản lý. Với `AF_UNIX` và `SOCK_STREAM`, các process dùng file descriptor để
trao đổi byte qua kernel.

```text
sensor_service
  socket → bind → listen → accept
                         ▲
                         │ connect
                 vehicle_middleware
```

`SOCK_STREAM` không giữ message boundary. Vì vậy protocol dùng newline framing:

```text
engine_rpm|1800|0\n
END\n
```

Sender phải xử lý partial write. Receiver phải đọc cho đến newline. EOF hoặc
peer disconnect phải được xem là lifecycle event, không phải dữ liệu hợp lệ.

## Thread/multithread liên quan

Mỗi service vẫn có thể có nhiều thread. Socket file descriptor là resource của
process; nếu nhiều thread cùng dùng socket, cần quy định ownership rõ ràng.
Trong milestone này, một thread chính sở hữu socket và `sensor_service` dùng
queue nội bộ trước khi gửi event.

Queue nội bộ và Unix socket giải quyết hai vấn đề khác nhau:

- queue: giao tiếp giữa threads trong cùng process;
- Unix socket: giao tiếp giữa processes.

## Vì sao chưa dùng shared memory

Telemetry event nhỏ, cần framing và disconnect detection. Unix socket đơn giản
hơn shared memory vì kernel quản lý việc truyền byte và lifecycle connection.
Shared memory sẽ chỉ phù hợp khi cần chia sẻ snapshot lớn hoặc throughput cao,
đồng thời phải tự thiết kế synchronization và crash recovery.

## Verification

```sh
cmake --build build
ctest --test-dir build --output-on-failure
./build/v1_process_launcher \
  ./build/sensor_service \
  ./build/vehicle_middleware
```

Kiểm tra protocol encode/decode, malformed message và server startup trước
client. Dùng `strace -f` để quan sát
`socket`, `bind`, `listen`, `accept`, `connect`, `send`, `recv` nếu tool có sẵn.
