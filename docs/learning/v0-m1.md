# V0-M1 — C/C++ and Linux process foundations

## Goal

Create the smallest buildable vehicle telemetry program and establish a clean
baseline for later memory and concurrency debugging.

## Concepts practiced

- A source program is compiled and linked into an executable file.
- A running executable is a Linux process.
- `VehicleTelemetry` is a value type with automatic object lifetime.
- Returning the telemetry object by value transfers a value to the caller;
  there is no manual `new`/`delete` ownership in this milestone.
- `const` communicates that the sample is not modified after creation.
- CMake describes the library, executable, and test targets.

## Why the project starts here

Threads and processes will later create multiple execution contexts and make
data ownership harder to reason about. Establishing explicit lifetime and
ownership first makes later synchronization problems easier to isolate.

## Verification

1. Configure and build from a clean build directory.
2. Run the telemetry executable.
3. Run the CTest test.
4. Use GDB to stop in `main` and inspect `telemetry`.
5. Use Valgrind to check for invalid memory access and leaks.

## Interview checkpoint

Before V0-M2, be able to explain:

- program versus executable versus process;
- stack, heap, and automatic object lifetime;
- RAII and why manual allocation is avoided here;
- compile versus link;
- what GDB, Valgrind, and CMake each contribute.
